# Matriz completa API pública IACP → IaCoC

OpenAPI desplegado leído mediante HTTPS autenticado, sin mutaciones, el 26/10/2026: `iacp-deployed-20261026-061.json` (IACP 0.10.1, 26 rutas / 28 operaciones). Forgejo HEAD observado: `47f5fd22800900b8f374881657662df78680c07b`. Copias de contratos publicadas en `contracts/forgejo-061/docs`. La igualdad de operationId/ruta no acredita que todos los detalles del runtime coincidan con Forgejo.

Inventario y tipos generados offline mediante `scripts/generate-iacp-client.mjs`; `iacp.generated.ts` conserva las operaciones públicas, mientras `crmActions` expone únicamente capacidades pertinentes. El transporte mantiene rutas fijas, no es proxy arbitrario. Los tipos generados no sustituyen validación runtime Zod ni autorización de IACP.

No hay endpoints públicos de introspección/gestión de identidades ni permisos. El tenant se acredita por observabilidad autenticada; no se inventan scopes ni se expone administración global. No existe endpoint de pedido/billing independiente: `commercial_context` son referencias opacas de orden/producto en crear, sin base comercial paralela.

### Faltante exacto para el E2E final desde navegador

La integración GUI está conectada al cliente OpenAPI generado para las 28 operaciones inventariadas. Lo que falta para declarar cierre E2E real no es una ruta de IaCoC: es una ventana autorizada de laboratorio con credencial operator, plan/Golden Image/red admitidos y permiso explícito para una KVM nueva desechable. En esa ventana habría que ejecutar una sola creación desde `/crm`, seguir su operación, comprobar inventario y luego recorrer únicamente las acciones lifecycle/red/acceso que IACP publique como elegibles. Esta revisión no lo ejecutó por la restricción explícita de no crear ni mutar recursos reales; tampoco toca VM 30029 ni actualiza la Stack empresarial.

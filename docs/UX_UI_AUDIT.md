# Auditoría UX/UI inicial de IaCoC

Fecha: 2026-10-28  
Rama: `feature/iacoc-ux-ui-overhaul`  
Base: `release/0.6.3-rc.10` con `origin/main` actualizado  
Alcance: shell, Overview, Operations, Events, Workers & Queues, Incidents & Recovery y administración visible en el navegador.

## Método y límites

La auditoría se ejecutó antes de modificar la aplicación. El producto se levantó en el contenedor de pruebas y el upstream utilizado por el navegador fue un fixture exclusivo de `tests/browser/`; no se copiaron fixtures al runtime ni se realizaron mutaciones reales de KVM, CRM, IACP o Proxmox.

Comando reproducible:

```text
docker compose run --rm iacoc-tests npm run test:e2e -- tests/browser/ux-audit.spec.ts
```

El escenario inspeccionó Chromium en 390, 768, 1024, 1366, 1440 y 1920 px, registró overflow del documento, tiempo hasta `DOMContentLoaded`, cantidad de filas/paneles y el menor tamaño tipográfico computado. También dejó capturas y una traza Playwright en [`docs/evidence/ux-ui/before/`](evidence/ux-ui/before/).

Skills y metodologías usadas realmente:

- [`visualize`](https://github.com/openai/codex) local: sistema de tokens, wireframes ASCII, jerarquía visual, controles de teclado, foco visible, responsive y `prefers-reduced-motion`.
- [`anthropics/skills/frontend-design`](https://github.com/anthropics/skills/tree/main/skills/frontend-design): dirección visual deliberada, tipografía con roles y revisión de la propuesta contra el brief. Se leyó su licencia Apache-2.0; no se copiaron archivos ni se instaló la skill en el host.
- [`vercel-labs/agent-skills/web-design-guidelines`](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines) y su guía remota: heurística de accesibilidad, formularios, navegación por teclado, estados de carga, overflow, tablas, URL state y movimiento reducido. No se incorporó código externo.
- WCAG 2.2 AA como lista de comprobación práctica y Playwright/Chromium para validar comportamiento, no solamente presencia de nodos en el DOM.

## Riesgos y límites que no se deben “arreglar” con UI

- `status`, `normalized_status`, `updated_at` y evidencia deben conservarse tal como los publica IACP; no se deben inferir heartbeats, workers, colas ni ausencia global de incidentes.
- La conexión continúa siendo autenticada, tenant-scoped y gestionada por el cliente de conexiones. La UI no hablará con Proxmox ni implementará un proxy arbitrario.
- Un rechazo de IACP se muestra fielmente. No se reintroducen cuotas históricas ni un total inventado del tenant.
- Los fixtures usados aquí son solo para la auditoría del navegador; no se copiarán al runtime.

## Verificación posterior

La misma auditoría se repitió después del rediseño. La medición tipográfica final cuenta únicamente nodos con texto visible y excluye `SVG/PATH`; el mínimo quedó en 12 px en las siete rutas auditadas. La tabla mantiene una ventana de 50 registros en Operations, mientras Overview renderiza 0 filas HTML porque su actividad es una lista semántica de 8 operaciones, no el historial completo.

| -------------------- | -----------------: | ------------------: | ----------------------------: | -------------------------: |
| Overview             |                0/6 |               12 px |                 8 actividades |                    65.2 ms |
| Operations           |                0/6 |               12 px |                            50 |                    91.0 ms |
| Events               |                0/6 |               12 px |                    48 eventos |                    62.1 ms |
| Workers & Queues     |                0/6 |               12 px |       arquitectura conceptual |                    59.0 ms |
